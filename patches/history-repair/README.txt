Master Koinos AI Node - repair Mainnet historical block 6,033,632

This optional owner-run utility repairs ONE known missing block-store record.
It does not install a new app, reset the chain, change node settings, access
wallets, enable RPC write methods, or start/stop your existing containers.

1. In Master, Stop the Koinos node and wait until it has stopped.
2. Quit Master completely from the tray. Leave Docker Desktop running.
3. Extract the entire ZIP to a folder and double-click Start-Repair.cmd.
4. Keep Master closed while the full block-store backup and repair run.
5. Only after REPAIR COMPLETE / SUCCESS, reopen Master and Start the node.
6. Check account_history logs for progress beyond 6,033,632; keep the backup.

The public API is unavailable while the node is stopped. Backup duration and
space depend on your existing block-store database, which may be large.
The default backup folder is beside basedir, under mainnet\history-repair-backups.
The .bak file is a complete Badger logical backup; retain its .json checksum.
The helper prints backup progress. A full disk or failed backup prevents the
repair write. A .partial file means backup did not finish; keep failure output.

To choose another backup drive, open PowerShell in the extracted folder:
  .\Repair-History.ps1 -BackupDirectory 'D:\KAI-repair-backups'
To run the read-only preflight alone:
  .\Repair-History.ps1 -CheckOnly
For a custom node directory, supply -NodeRoot with the mainnet folder.

Verification and limits
-----------------------
The payload was fetched independently from api.koinosblocks.com and
api.koinos.io. Both returned identical JSON block and receipt values; see
provenance.json. The block is pinned by its ID and its canonical header hash.
The helper verifies both local neighbors, locates the pinned successor in
the local head's ancestry, reconstructs skip-list links using upstream code,
and simulates all 500 blocks/receipts in the next history batch before writing.

Receipt contents rely on agreement between those two trusted RPC endpoints.
They are not independently regenerated by replaying historical chain state.
The helper checks an available receipt state root against the local successor;
that field is absent in this pinned payload. It does not claim to validate the
entire history or all receipt contents cryptographically.

After a full backup, a single conditional Badger transaction inserts ONLY the
missing record. The highest-block record and other records are retained. The
500-block batch is checked again. Existing target records are never overwritten.
Another missing record in that batch causes preflight to fail without repair.
This tool runs offline inside the already-installed block-store Docker image,
with no network, no published ports, and only database/backup/package mounts.

Recovery if needed
------------------
Keep the node stopped and share the failure before replacing any data.
The Linux helper supports --restore BACKUP --sha256 EXPECTED --db NEW_EMPTY_DIR.
It checks the backup hash and will only restore into an empty directory; it
never replaces the live database. Restoring requires a separate owner action.
The original .bak/.json files must be retained until indexing is confirmed.
